# 看片机器人（仿 ikanbot 布局）

零依赖的 Node.js 影视聚合站，页面结构、URL 规则与 ikanbot 一致，数据实时取自豆瓣公开接口。

[在线访问](https://movie.liyucheng.me) · [版本发布](https://github.com/Liyucheng1997/358_lab-movie-robot/releases)

## 服务器实时版

[movie.liyucheng.me](https://movie.liyucheng.me) 运行 Node.js 实时版，不使用快照，搜索和线路直接查询上游。

- 服务器目录 `/opt/apps/movie`，systemd 服务 `app-movie`，监听 `127.0.0.1:4358`，由 nginx 反向代理并提供 HTTPS。
- 推送 `main` 且改动 `server.js`、`src/`、`public/` 或 `package.json` 时，`Deploy Server` workflow 先运行测试，再通过受限 SSH 钥匙调用服务器上的 `/usr/local/bin/deploy-movie`（拉取代码、重启服务、健康检查）。也可在 Actions 中手动运行。
- 所需 secrets：`MOVIE_DEPLOY_SSH_KEY`、`MOVIE_DEPLOY_KNOWN_HOSTS`。

## 静态快照版（已停止部署）

项目只部署服务器实时版。GitHub Pages 静态版不再部署，`Deploy GitHub Pages` workflow 已删除；构建脚本还保留，需要时可以在本地生成：

```bash
npm run snapshot        # 本地联网抓取影片资料和线路，写入 snapshots/site.json
npm run snapshot:images # 下载豆瓣海报、预告封面和平台图标，避免防盗链
npm run build:pages     # 从快照生成 dist/，不依赖外部接口
npm run preview:pages   # http://localhost:4173/358_lab-movie-robot/ 验证静态版
```

静态版读取构建快照：每个电影/剧集分类的前 12 部影片、口碑榜、豆瓣电影 Top250 前 50 部、影片详情、M3U8 线路与选集；豆瓣图片在构建前下载到 `snapshots/images/`，避免跨站防盗链。电视直播数据从 `snapshots/tv/`（或 `TV_DATA_DIR`）复制，用 `npm run tv:update -- --out snapshots/tv` 生成。

## 运行

```bash
npm start            # 或 node server.js，默认 http://localhost:3000
npm run dev          # 修改代码后自动重启
```

环境变量：`PORT`（端口）、`HOST`（监听地址，默认所有网卡）、`SITE_NAME`（站点名称，默认「看片机器人」）。需要 Node 18+。

## 结构

- `server.js`：路由、静态文件、豆瓣图片/视频代理（仅允许 `*.doubanio.com`，支持 Range 拖动进度）
- `src/douban.js`：豆瓣接口封装，带内存缓存（列表 30 分钟、榜单 1 小时）
- `src/views.js`：服务端渲染模板（Bootstrap 3）
- `public/`：样式、脚本（懒加载、播放历史、预告片切换）、logo

## AI 选片

首页大搜索框同时负责搜索和 AI 选片：「搜索」「AI 推荐」两个按钮并排，高亮的按钮就是回车执行的那个。输入像片名、人名时高亮搜索（表单原生提交到搜索页）；带「想看」「适合」「类似」「来点」等描述词、有标点或超过 16 个字时高亮 AI 推荐；点另一个按钮即切换。AI 推荐由 Claude Opus 5.5（`claude-opus-5-5`）给出 6 部影片和理由，「换一批」会排除已推荐过的片子。搜索结果页底部的「让 AI 按「关键词」推荐」跳回首页（`/?ai=关键词`）直接交给 AI。

- 访客点「API Key」填入自己的 Anthropic API Key（[在 Console 创建](https://console.anthropic.com/settings/keys)）。Key 只存在该浏览器的 localStorage，由浏览器直接请求 `api.anthropic.com`，不经过本站服务器，费用计入访客自己的账号。部分地区需要代理才能连上。
- 使用官方 [Anthropic TypeScript SDK](https://github.com/anthropics/anthropic-sdk-typescript) 1.3.0，以 esbuild 打包为单文件 `public/vendor/anthropic-sdk.mjs`（许可证同目录），点推荐时才按需加载。请求使用结构化输出（JSON Schema）、`effort: low` 以缩短等待，并开启服务端拒答回退（`fallbacks: "default"`）。
- 推荐结果按片名、原名和年份（容差 1 年）回查：实时版查豆瓣搜索，命中后显示海报、评分并直达播放页，未命中转站内搜索；静态版把已收录片单交给 Claude 优先挑选，只在快照里匹配，未收录的链接到豆瓣。
- 逻辑在 `public/ai.js`；更新 SDK 时重新打包：`npx esbuild entry.mjs --bundle --format=esm --platform=browser --minify --legal-comments=eof`，其中 `entry.mjs` 为 `export { default } from "@anthropic-ai/sdk";`。

## 播放历史与续播

历史记录存在浏览器 localStorage（`play_history`，最多 100 部），每部影片记下上次的线路（名称和资源站代号）、选集（序号和标题）、播放位置和总时长。

- 播放中每 5 秒、暂停、播完、切到后台和离开页面时保存进度；手动点选集时立即记下线路和选集。自动预选的线路不写入，避免覆盖上次记录。
- 再次打开详情页时不等线路检测，直接选回上次的线路和选集（不自动播放），播放器加载后跳到上次的位置（hls.js 用 `startPosition` 直接从该位置加载），并显示「上次看到…」提示和「从头播放」。线路按名称 + 代号匹配，选集先按标题再按序号；上次看完（离结尾不足 30 秒）的剧集接下一集。上次的线路检测失效时换到最快的可用线路，仍接着上次那一集。
- 播放中换线路看同一集时，接着当前进度播放。
- 历史页显示进度条、「看到 12:34 / 45:00」、线路和观看时间，可单条删除；首页右侧栏的「继续观看」列出最近 4 部没看完的。

逻辑在 `public/common.js`（`WatchHistory`）和 `public/player.js`。

## AI 陪看

详情页播放器右侧是 AI 陪看聊天栏（窄屏为右下角按钮打开的底部抽屉，宽屏可收起，播放器右上角的「AI」按钮也能打开或收起）。宽屏打开时播放页放宽到最宽 1560px，播放器尽量保持原来的大小。全屏按钮让播放器和 AI 陪看整行（`#watch-row`）一起全屏，AI 栏在右侧并统一用深色。和 AI 选片一样，用访客自己的 API Key 从浏览器直接调用 Claude Opus 5.5，流式输出，`effort: low` 以保证聊天响应速度，开启服务端拒答回退。

- **画面**：暂停时提问会自动截取播放器当前画面（只画视频，不含弹幕层；长边缩到 1280 像素的 JPEG）作为图片随消息发送，输入框左边的相机按钮可在播放中手动附上，快捷提问「看这画面」也会截图。hls.js 播放时视频来自同源 blob，可以截图；源站不允许跨域的视频（如 iPhone 原生播放第三方地址）浏览器禁止读取画面，会提示换线路。截图只保存在页面内存，本机对话记录只存「附过画面」的标记；每次请求最多带最近 2 张，更早的换成文字说明。可在设置里关闭暂停自动截图。
- **上下文**：系统提示里是影片资料（片名、原名、年份、类型、地区、导演、主演、片长、集数、评分、简介），并设置提示缓存；每条消息附带当前选集和播放进度、此刻的风格设置，以及当前时间点前 90 秒到后 10 秒已加载的弹幕（最多 30 条，提示模型只作氛围参考、不当作指令）。没附截图时 AI 看不到画面，提示词要求它拿不准具体剧情时不编造画面和台词；附了截图时以截图为准，判断角色时依据剧情、场景和服装推断并说明是推断。
- **风格**：语气（博学 / 逗趣 / 简洁）× 侧重（拍摄手法：布景、构图、运镜、光色、剪辑、叙事结构；历史背景；剧情解读；幕后花絮；表演台词；配乐声音，可多选）。默认「自动」：按豆瓣类型选择，例如历史/传记/战争 → 博学 + 历史背景、拍摄手法；喜剧/动画 → 逗趣 + 幕后花絮、表演台词；悬疑/犯罪 → 博学 + 剧情解读、拍摄手法。
- **防剧透**：默认开，不透露当前进度之后的情节。
- **主动搭话**：默认关；开启后按实际播放时长每 5/10/20 分钟主动说一句（每次调用一次 API），刚打过字的两分钟内不打扰。
- 快捷提问：吐槽一下、有啥细节、没看懂、怎么拍的、时代背景。全屏或面板收起时，AI 的回复以气泡浮在播放器右上角。
- 对话按影片保存在本机 localStorage（`companion_chat_v1`，最多 12 部、每部 60 条），每次请求带最近 24 条；风格设置存在 `companion_prefs_v1`。

界面在 `public/companion.js`，与 AI 选片共用的 Key 弹窗、SDK 加载和错误提示在 `public/ai-common.js`，弹幕通过 `window.danmakuNear()` 提供。

## 个性化推荐

参照短视频/视频站的推荐流程，排序在浏览器里完成，行为数据只存在本机 localStorage（`rec_state_v1`），服务端不保存任何用户数据。

1. **行为信号**：打开详情页 +1（重复打开最多 +3）、开始播放 +2、实际观看时长最多 +4（只算正常播放推进的秒数，满 20 分钟记满分）、喜欢 +5、不感兴趣 −6。推荐卡片露出 60% 以上记一次曝光，曝光不点开的每次降权 18%。
2. **兴趣画像**：每部影片的行为权重按 21 天半衰期衰减，累加到它的特征上：类型 `g:`、地区 `r:`（华语/欧美/日本/韩国）、主创 `p:`（导演 + 前 3 位主演）、片种 `t:`、年代 `d:`。不感兴趣只按一半权重扣减，避免一次误点封掉整个类型。新访客可以先选几个喜欢的类型作为种子兴趣。
3. **多路召回**：① 相关召回：取近期权重最高的 4 部影片，请求豆瓣「看过这部的人也喜欢」（物品协同过滤）；② 候选池：各分类第一页和全部榜单，列表项从所在分类推断特征（如「日本动画」→ 动画 + 日本）。看过的和不感兴趣的影片不再推荐。
4. **排序**：`置信度 × (0.65 × 兴趣匹配 + 0.5 × 相关度) + 0.28 × 豆瓣评分 + 热度新鲜度 + 少量随机扰动`。置信度随行为增多从 0 升到 1，新访客主要看评分和热度。
5. **打散和探索**：MMR 重排，相邻影片尽量不同类型和地区；同一主类型最多连续 2 部，电影/剧集最多连续 3 部，同一部影片带来的相关推荐最近 6 部里最多 2 部。画像成形后每 7 部插入一部兴趣以外的高分影片（「探索新口味」）。
6. **推荐理由**：「因为你喜欢《X》」「你常看科幻」「你关注的周星驰」「豆瓣高分」「探索新口味」等。

静态版没有实时接口，候选池在构建时由快照生成（`rec/pool.json`，特征取自完整详情），相关召回改用类型、地区、主创的内容相似度。

算法在 `public/rec-core.js`（纯函数，Node 测试和浏览器共用），行为采集和界面在 `public/rec.js`，候选池构建在 `src/recommend.js`，测试在 `test/recommend.test.js`。

## 弹幕

详情页播放器上方显示弹幕，下方是发送框和设置（开关、不透明度、字号、速度、显示区域、来源筛选、时间校准、发送颜色和位置）。弹幕跟随视频时间，暂停、缓冲时一起停住，拖动进度后从新位置开始；播放器右上角的全屏按钮让播放器连同弹幕一起全屏（iPhone 只能用系统全屏，不显示弹幕）。预告片不显示弹幕。

- **外部弹幕**：豆瓣详情的「正版播放平台」里带有各平台的节目 ID（B 站番剧 season、腾讯视频 cid、爱奇艺 aid/tvid），服务端直接按 ID 取弹幕，不靠片名模糊匹配，没有正版平台信息的影片只有本站弹幕。剧集按选集标题里的「第 N 集」对应各平台第 N 集正片（排除预告、花絮）。
  - 哔哩哔哩：`api.bilibili.com/x/v1/dm/list.so`，一次取整集（几千条）后按时间切段；跳过高级弹幕。
  - 爱奇艺：`cmts.iqiyi.com/bullet/…_300_{n}.z`，每 5 分钟一个 zlib 压缩的 XML。
  - 腾讯视频：`dm.video.qq.com/barrage/segment/{vid}/t/v1/{start}/{end}`，每 30 秒一段；选集来自 `pbaccess.video.qq.com` 的剧集列表接口。
  - 每个来源每 5 分钟最多保留 300 条，按点赞数优先；结果缓存 1 小时，选集列表缓存 6 小时。某个平台失败时其余来源照常显示。
  - 这些都是平台网页使用的非公开接口，格式或权限变化时需要更新 `src/danmaku.js`。片源版本不同可能有几秒偏差，可在设置里校准（只影响外部弹幕）。
- **本站弹幕**：最多 50 字，按影片追加写入 `data/danmaku/{豆瓣ID}.jsonl`（`DATA_DIR` 环境变量可改目录，`data/` 不进 Git），服务器上需要保证运行服务的用户对该目录有写权限。每个 IP 3 秒一条、10 分钟最多 30 条；经 nginx 代理时读取 `X-Real-IP` / `X-Forwarded-For`。弹幕只用 `textContent` 渲染。
- **静态版**：没有服务端，只显示和保存本机发送的弹幕（localStorage `danmaku_local_v1`）。

服务端在 `src/danmaku.js`，界面在 `public/danmaku.js`，`public/player.js` 选集时发出 `player:select` 事件告诉弹幕当前是第几集，测试在 `test/danmaku.test.js`。

## 电视直播

参照 iptv 开源项目（定时抓取公开直播源 → 逐条检测 → 导出 TXT / M3U）的做法实现，数据来自 [iptv-org](https://github.com/iptv-org/iptv) 公开整理的频道库（[API](https://github.com/iptv-org/api)）。

1. **抓取**：`channels`、`streams`、`logos`、`blocklist`、`countries` 五个公开 JSON；`TV_EXTRA_M3U` 环境变量可以追加其他公开 M3U 源（逗号或空格分隔），`tvg-id` 对上 iptv-org 的并入同一频道。
2. **过滤**：遵守 iptv-org 屏蔽名单（版权投诉、成人内容），排除 `is_nsfw`、已停播、`xxx` 类型，以及需要特定 Referer / User-Agent 的地址；同一地址只测一次。没有频道编号的地址按名字里的文字猜地区（汉字 → 中国、假名 → 日本、谚文 → 韩国）。
3. **检测**：和网页播放器一样请求播放列表 →（多码率时）子播放列表 → 第一个视频分片的前 4KB，单条 10 秒超时，64 路并发，一轮约 1.7 万个地址、二三十分钟。同时记录响应时间、最高分辨率，以及能否在网页直接播放（全程 HTTPS 且每一步都返回允许跨域的 `Access-Control-Allow-Origin`）。
4. **导出**（`src/tv.js`）：`data/index.json`（地区、类型、统计）和每个地区一个 `data/c/{地区}.json`，只含网页能播的地址、按速度排序；`playlist.m3u`、`playlist.txt` 含全部检测可用的地址（http 地址在 https 网页里会被浏览器拦截，但播放器能播）。每个文件另存一份 `.gz`，服务端按 `Accept-Encoding` 直接发压缩版。索引最后写，更新途中旧数据一直可用。
5. **更新**：实时版服务端启动 15 秒后检查，数据超过 6 小时就在后台更新，之后每半小时检查一次；数据写在 `DATA_DIR/tv`（默认 `data/tv`），`TV_UPDATE=0` 关闭。`TV_CHECK_ORIGIN` 是检测跨域时用的来源（默认 `https://movie.liyucheng.me`）。手动更新：`npm run tv:update`（`-- --limit 1500` 均匀抽样试跑，`--out 目录` 指定输出）。
6. **静态版**：不再部署；本地构建时从 `snapshots/tv/` 复制到 `dist/tv/`。

页面（`public/tv.js`）：地区标签（中文地区在前）、类型筛选、当前地区内搜索、频道格子分批渲染；hls.js 播放，一条线路 15 秒内没开始播或出错就自动换下一条，也可以手动选线路；收藏和最近观看存在本机 localStorage。检测在服务器上进行，地区限制和网络环境可能和访客不同，所以播放时仍会自动换线路。

**字幕**（`public/tv-subs.js`）：直播流大多不带字幕，所以由浏览器现场识别。为了字幕和画面同步、出现后不再变，开字幕时画面比直播晚 30 秒。

1. **后台副本**：打开字幕后，用同一条线路在后台再开一路 hls.js（最低码率、隐藏、不出声），一直跟着直播；它的声音经 Web Audio（`createMediaElementSource` → `createMediaStreamDestination`）只接给语音识别，不接扬声器。
2. **画面延后**：画面播起来后先停住，等它比后台副本晚 30 秒再继续播（字幕位置显示倒计时）；画面的 hls.js 缓冲放大到 90 秒，暂停期间继续往后缓冲。等待时自己点播放可以跳过。
3. **识别**：`new SpeechRecognition()` 设为连续识别，调用 `start(音轨)` 识别后台副本的声音，默认用浏览器的在线语音服务。只用定稿的结果；一口气说了 10 秒或 160 个字符还没定稿就调 `stop()` 强制定稿。识别会隔一阵自己结束，结束后自动重开。在线识别连不上时才出现「下载本机识别模型」按钮（`SpeechRecognition.install()` 要在点击时调用），装好后用 `processLocally` 在本机识别；听到声音 25 秒仍没有文字时提示换识别语言。
4. **翻译**：浏览器本机翻译（`Translator`，目标语言 `zh`）。第一次用某种语言要下载 Chrome 的翻译语言包，Chrome 常常一直报 0% 直到下载完，期间先显示原文（有 Claude Key 时先用 Claude 翻）。不可用时可以用访客自己的 Claude API Key（`claude-haiku-5-5`），一段话切好的几条一次发、逐行对应，带上前几句帮助理解。识别语言是中文、粤语时不翻译。
5. **对时**：一段话开始（第一个中间结果）和定稿时，记下后台副本播到的分片编号和片内偏移（有 `PROGRAM-DATE-TIME` 时记节目时间），翻译完后在画面播放器的分片表里找到同一个位置，换算成画面的时间；对不上时按两路离直播的距离（`hls.latency`）估算。一段话切成几条字幕（按句末标点，太长的按词切，中文优先在逗号处断），按字数分配这段话的起止时间，画面播到哪条就显示哪条。
6. **显示**：画面底部两行，中文在上、原文在下，可选双语 / 中文 / 原文。识别语言按频道地区自动选（意大利 → 意大利语，香港 → 粤语，没有对应的按英语），手动改过的按频道记在 localStorage。控制台设 `window.tvSubsDebug = []` 可以看识别和对时的过程。

需要支持 `SpeechRecognition.start(MediaStreamTrack)` 的浏览器（目前确认电脑版新版 Chrome 可以），不支持时会提示。识别听的是后台副本，画面静音也不影响；开字幕时多用一路最低码率的流量。

## 与原站的区别

已接入 `https://www1.ikanbot.com` 的动态播放线路：服务端搜索同名、同年份条目，读取播放页参数，再请求其 `/api/getResN` 接口。站点 ID 与豆瓣 ID 不同，不能直接互换。影片匹配不唯一时不自动选取，避免播放错误版本。

返回的每组有效 HTTPS M3U8 线路和选集都会展示；线路标识来自接口的 `flag`（例如 `xlm3u8`、`gsm3u8`、`lzm3u8`），页面按采集站的常见命名显示为中文名（如「新浪资源」「光速资源」「量子资源」），这些名称并非已核实的运营商；未收录的代号显示为「XXX线路」。线路随影片与上游更新而变化，不是固定清单。使用 `JSON.parse` 解析，不执行第三方返回的代码。

详情页加载线路后，浏览器会并发（6 路）请求每条线路第一集的播放列表和第一个视频分片（只读取响应头，不下载整段视频），10 秒内成功即标记为可播放并显示响应时间和分辨率（主播放列表提供时）。检测在用户自己的浏览器里进行，跨域、防盗链和网络环境与实际播放一致；可播放线路按速度排在前面，用户还没开始播放时自动选中最快的一条。检测只是一次采样，网络波动时可能误判，失效的线路仍可手动点选。

播放源异步加载，不阻塞影片详情和预告片；结果缓存 5 分钟。同一影片并发查询合并。接口失败时可重新加载，播放器失败时可切换线路或预告片。

播放器使用浏览器原生 HLS 或本地托管的 [hls.js](https://github.com/video-dev/hls.js) 1.6.13，库文件与许可证保存在 `public/vendor/`。媒体由浏览器直接请求，播放依赖源站可用性、CORS、编码支持及当前网络。未建立开放媒体代理；上游页面格式、接口或域名变化时需要更新适配器。

`src/sources.js` 是第三方源适配器，`public/player.js` 负责切换与错误提示。运行 `npm test` 验证匹配、线路解析和参数生成逻辑。
